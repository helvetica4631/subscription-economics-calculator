# Проверка перед заявлением о готовности

Доказательства раньше утверждений. Всегда.

```
НИКАКИХ ЗАЯВЛЕНИЙ О ГОТОВНОСТИ БЕЗ СВЕЖЕГО РЕЗУЛЬТАТА ПРОВЕРКИ
```

Не запускала проверку в этом сообщении - не говори, что она проходит.

## Правила проекта

Скилл общий для `executor`, `reviewer` и `orchestrator`.

- В отчёте: что проверено, чем, что получилось, что НЕ проверено. Исполнитель и ревьюер пишут технически, оркестратор пересказывает пользовательнице простым языком с объяснением терминов.
- Сверяй результат с контрольными примерами из спеки (`specs/<тема>/spec.md`), а не только с тем, что проверки зелёные.
- Веб-приложения проверяй во встроенном браузере: открой, пройди сценарий из критериев приёмки, проверь, что на экране то, что ожидалось, и нет ошибок в консоли страницы. Утверждение "работает" без этого недопустимо.
- Отчёту другого агента не верь: смотри изменённые файлы и сам запускай проверку.
- Проверку исполнителя повторяет отдельный ревьюер со свежим контекстом, а оркестратор сверяет с контрольными примерами сам; ничьё мнение не заменяет запуска.
- Нет возможности проверить (нет доступа, нет согласия на установку инструмента, нет ключа): так и скажи, не заменяй проверку предположением. Исполнитель и ревьюер возвращают это оркестратору, оркестратор просит у пользовательницы. `.env` не открывать.

## Порядок

Перед любым заявлением о статусе или выражением удовлетворения:

1. **Определи:** какая команда или действие доказывает это утверждение.
2. **Запусти** целиком, свежо.
3. **Прочитай** весь вывод, код завершения, число падений.
4. **Сверь:** подтверждает ли результат утверждение. Нет - сообщи фактический статус с доказательством. Да - утверждай с доказательством.
5. Только после этого заявляй.

Пропустила шаг - это ложь, а не проверка.

## Что чем доказывается

| Утверждение | Нужно | Не годится |
|---|---|---|
| Проверки проходят | Вывод команды: 0 падений | Прошлый запуск, "должно пройти" |
| Сборка работает | Команда сборки: код завершения 0 | "Линтер чист", "в логах всё хорошо" |
| Ошибка исправлена | Исходный симптом больше не воспроизводится | Код поменяла, значит исправлено |
| Регрессионная проверка | Цикл: красный -> зелёный; убрать исправление - красный, вернуть - зелёный | Один зелёный запуск |
| Агент справился | Файлы изменены и проверка запущена тобой | Агент пишет "успех" |
| Требования выполнены | Построчная сверка со спекой и контрольными примерами | "Проверки прошли" |
| Веб-интерфейс работает | Сценарий пройден во встроенном браузере, снимок / текст страницы сверены | Логика проверена, значит экран верен |

## Красные флаги: остановись

Слова "должно", "наверное", "вроде бы"; радость до проверки ("Готово!", "Отлично!"); коммит или передача без проверки; вера отчётам агентов; частичная проверка; "я устала". Любая формулировка, подразумевающая успех без запуска проверки.

| Отговорка | Реальность |
|---|---|
| "Теперь должно работать" | Запусти. |
| "Я уверена" | Уверенность не доказательство. |
| "Линтер прошёл" | Линтер не сборка. |
| "Агент сказал, что готово" | Проверь сама. |
| "Частичной проверки хватит" | Частичная проверка ничего не доказывает. |
| "Другие слова, значит правило не про это" | Дух важнее буквы. |

## Когда применять

Всегда перед: любым утверждением об успехе, пересказом результата, коммитом, переходом к следующей задаче, передачей работы агенту. Правило касается точных фраз, пересказов, синонимов и намёков на успех.

После проверки обнови «Актуальное состояние» в `specs/<тема>/progress.md`: что проверено, чем, что нет. Ревьюер журнал не правит: его результат - отчёт.
