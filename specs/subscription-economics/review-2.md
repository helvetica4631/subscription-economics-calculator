## Находки

### 1. Важная. Формула LTV/CAC подставляет округлённый LTV: результат не следует из показанных чисел, у порога - противоречие с вердиктом
- Где: src/view.js, `describeFigures`, `formula` у `ltvCac`: `'LTV ÷ CAC = ' + ltvText + ' ÷ ' + k + ' = ' + ratioText`, где `ltvText = formatRu(r.ltv, 2)`.
- Что не так: справа стоит LTV/CAC от неокруглённого LTV, слева - округлённый LTV. Случайный перебор 40 000 обычных вводов (цена 0,5-200, маржа 1-100, отток 0,5-20,5, CAC 1-500): в 124 случаях пересчёт подставленных чисел даёт другое значение (`316,54 ÷ 107,85 = 2,93`, а на калькуляторе 2,94). Хуже всего у порога: ввод 9,9999 / 60 / 2 / 100 (пороги 3, 12) на экране даёт
  `300,00 LTV` и `LTV ÷ CAC = 300,00 ÷ 100 = 2,99997`, метка «порог 3 не пройден», вердикт «Пока нет». В пояснении к LTV тут же «клиент должен приносить не меньше, чем CAC × 3»: продакт видит 300 при CAC 100 и не понимает, почему порог не пройден. Правило formulas.md «Показ значений рядом с порогом» закрыло «3,00 рядом с не пройден» для LTV/CAC, но не для LTV, из которого оно считается.
- Последствие: ровно тот случай, ради которого продакт открывает калькулятор (граница), выглядит как ложная арифметика. Анти-цель спеки «цифры, про которые непонятно, как посчитаны».
- Воспроизвести: открыть index.html, ввести 9,9999 / 60 / 2 / 100, смотреть раздел 4.

### 2. Мелкая. Месяцы: значение с 1 знаком и итог формулы с 2 знаками округляются независимо и расходятся
- Где: src/view.js, `paybackValue`/`paybackFormulaValue`, `lifetimeShort`/`lifetimeLong`.
- Что не так: значение округляется от точного числа до 1 знака, формула показывает 2 знака. Когда точное значение x,x45…x,x4999, видно `12,3 месяца` и `1 ÷ 0,081 = 12,35` (продакт ждёт 12,4). Перебор 40 000 вводов: срок жизни расходится в 2461 случае, окупаемость в 2040 (около 5-6%). Подтверждено на экране: отток 8,1 → «12,3 месяца», «= 12,35».
- Последствие: цифра и её формула выглядят несогласованными у каждого двадцатого ввода.
- Воспроизвести: 10 / 70 / 8,1 / 60.

### 3. Мелкая. Маржа «недостижимо» с нужным значением «100%»
- Где: src/view.js, `describeRow`, ветка `over100`: `plain(calc.roundHalfUp(change.target, 2))`.
- Что не так: нужная маржа немного выше 100% (100,003%) округляется до «100%», текст: «Маржа не может быть выше 100%, а для порогов понадобилось бы 100%». Округление здесь не в сторону порога, в отличие от остальных целей.
- Воспроизвести: 10 / 50 / 5 / 66,6687 (проверено на экране).

### 4. Мелкая. Порог с большим числом знаков, чем у показа: значение по ту сторону порога
- Где: src/calc.js `formatNearThreshold` (используется экраном): добавляет знаки только при точном равенстве с порогом.
- Что не так: порог окупаемости 12,24, окупаемость 12,245: «Окупаемость 12,2 месяца дольше порога 12,24». Аналогично для LTV/CAC при пороге с 3-4 знаками.
- Воспроизвести: 10 / 50 / 2 / 61,2251, порог окупаемости 12,24 (запуск view.describe).

### 5. Мелкая. Пояснение к сроку жизни сравнивает неокруглённые значения
- Где: src/view.js, `beforeLeaving`.
- Что не так: 10 / 50 / 6 / 83,3: окупаемость «16,7 месяца», срок жизни «16,7 месяца», текст «Окупаемость 16,7 месяца короче срока жизни». Проверено на экране.

### 6. Мелкая. Крайние значения показываются как ложные или нечитаемые цифры
- Окупаемость меньше 0,05 месяца: 1000 / 100 / 5 / 40 → «Окупаемость 0,0 месяца», в формуле «= 0,04». Продакт видит нулевую окупаемость.
- Отложенное в блоке 1 теперь видно на экране: цена 1000000000, CAC 9999999999,99 → LTV «10000000000,01» (верно 10000000000,00); цена 10^21 → «1,0000000000010001e+22».

### 7. Мелкая. DOM-часть экрана не покрыта ни одной проверкой
- Где: src/page.template.html (скрипт страницы), tests/.
- Порчи в копии проекта, после каждой - пересборка и `npm test`:
  - убрано `byId('results').hidden = true` (цифры остаются при ошибке) - выжила;
  - ошибки у полей никогда не показываются - выжила;
  - трудность из селектов игнорируется - выжила;
  - предупреждение не выводится - выжила;
  - нет обновления по `input` - выжила.
  20 порч src/view.js (метки порогов, формулы, знаки, уточнение у порога, причины, порядок, noChanges, предупреждение) - все убиты.
- Последствие: сейчас поведение верно (проверено в браузере), но при исправлениях по этому ревью любая регрессия в сокрытии цифр при ошибке пройдёт зелёной. Решение записано в журнале с риском.

### 8. Мелкая. Тексты для продакта без технических знаний
- Формулы целей записаны как `max(… ; …)`/`min(… ; …)` без промежуточных значений: видно `max(3 × 60 × 0,06 ÷ 0,70 ; 60 ÷ (12 × 0,70)) = 15,43 (округлено вверх)`, но не 15,43 и 7,14, из которых выбран максимум. Пояснение «берётся большее из двух значений в скобках» есть, но проверить выбор нельзя. Решение записано в журнале.
- «На каждую потраченную на привлечение единицу приходится 1,94 прибыли» - пропущено «единицы».
- «дольше порога 12,5 месяцев» - для дробного числа «месяца».
- Вид: подпись цифры (`.num .v .note`) наследует высоту строки от шрифта 24px, на 375 px подпись из двух строк идёт с большим разрывом между строками (снимок Chrome, тёмная тема, и встроенный браузер).

## Пункты «На что смотреть ревьюеру» (plan-2.md)
1. Цифры при любой ошибке скрыты: ошибки полей, порогов и `general` проверены в браузере, при переходе из корректного ввода в ошибочный цифры исчезают. Автоматической проверки нет (находка 7).
2. `3,00` рядом с «не пройден»: для LTV/CAC и окупаемости не воспроизводится; аналог для LTV - находка 1; для дробного порога - находка 4.
3. Подстановки: доли `0,005`, `0,655`, введённые числа с запятой совпадают с вводом (пример 6, ввод 9,9999, 66,6687, 61,2251). Расхождения подстановки и результата - находки 1, 2.
4. Селекты и поля не пересоздаются (в шаблоне постоянная разметка, пересоздаются только карточки цифр), порядок пересчитывается.
5. index.html совпадает со сборкой и содержит src/*.js дословно (проверка сборки и `cmp`); ввод `<img src=x onerror=alert(1)>` даёт ошибку у поля, вывод только через `textContent`, `innerHTML` в коде нет.
6. 375 px: прокрутки нет, длинные формулы переносятся.

## Что не проверила и почему
- Тёмная тема во встроенном браузере: он показывает локальный файл как снимок и всегда в светлой схеме; проверено в Chrome.
- Хранение во встроенном браузере: localStorage там заблокирован для снимка data:, проверено в Chrome.
- Восстановление полей браузером при «назад/вперёд» и после закрытия вкладки в обычном (не изолированном) профиле Chrome не проверялось; `autocomplete="off"` стоит.
- Экранные чтецы (частые `role="alert"` при каждом нажатии) не проверялись: нет инструмента.
- Перебор находок 1 и 2 выполнен на модуле view.js в Node, а на экране подтверждены по одному примеру каждой; DOM выводит тот же текст через `textContent`.
