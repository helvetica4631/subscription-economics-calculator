## История / изменения
- Решение: подстановки в формулах сходятся с результатом - у подставляемых LTV, итога окупаемости и срока жизни добавляются знаки (до 8), пока округление показанных чисел не даёт показанный результат; для LTV/CAC в подстановке иногда больше знаков, чем в карточке LTV - так следует принципу «цифры сходятся» - риск: длинные числа вида 299,997 у границы порога.
- Решение: formatNearThreshold получил необязательный 5-й параметр kind ('atLeast' | 'atMost'): показанное значение должно быть по ту же сторону порога, что и вердикт (в том числе для пройденного порога и порогов с лишними знаками); без параметра поведение прежнее - риск нет, старые вызовы не менялись.
- Решение: значение LTV сравнивается с порогом R × CAC, у границы показывается с лишними знаками (299,997 вместо 300,00) - иначе видно «300 при CAC 100, порог не пройден» - риск: карточка LTV иногда с 3-5 знаками.
- Решение: при равных округлённых окупаемости и сроке жизни пояснение называет оба значения с большим числом знаков («Окупаемость 16,66 месяца короче срока жизни 16,67 месяца») - риск: значение в карточке срока жизни (16,7) короче, чем в пояснении.
- Решение: маржа «недостижимо» при цели чуть выше 100% показывает цель с таким числом знаков, чтобы было видно «больше 100» (например 100,003%), и добавляет «то есть больше 100%» - риск нет.
- Решение: находка 7 закрыта проверкой с минимальной подменой DOM (tests/page-dom.test.js: vm, ~40 строк заглушки document, без установок) - реальный браузер не заменяет, внешний вид не проверяет - риск: заглушка может разойтись с настоящим DOM.
- Решение: тексты и числа экрана вынесены в src/view.js (SubEconView), в index.html встроены calc.js, view.js и код страницы из шаблона - логика экрана проверяется автоматически, DOM-код тонкий - DOM-часть проверена только в браузере, автоматических проверок на неё нет.
- Решение: ошибка пустого поля показывается после первого ввода в него или ухода из поля; на непройденном поле без касания видна только подсказка "Введите все четыре показателя" - при открытии страница без красных ошибок - риск: продакт, не коснувшийся поля, видит общую подсказку без указания поля.
- Решение: в формулах таблицы подставлены введённые числа и показано итоговое округлённое значение с пометкой "округлено вверх/вниз" без промежуточных значений - чтобы не дублировать расчёт из calc.js - риск: промежуточные max/min не видны.
