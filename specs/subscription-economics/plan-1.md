# Экономика подписки, блок 1: план

**Спека:** specs/subscription-economics/spec.md, блок 1; правила: formulas.md
**Цель:** модуль расчётов (ввод, цифры, предупреждение, вердикт, что изменить, порядок), проверенный автоматически на Node.js 22.
**Подход:** один классический скрипт `src/calc.js` (обёртка UMD без import/export): в браузере по `file://` подключается тегом `<script src>` и даёт глобальный `SubEconCalc`, в Node отдаётся через `module.exports`. Проверки на встроенных `node:test` и `node:assert`, установок нет.
**Стек:** JavaScript (ES2020), Node.js 22.

## Глобальные ограничения
- Открытие двойным щелчком, без сервера и сборки; модули ES не работают через file://.
- Ничего не отправлять в сеть, не сохранять.
- Без комментариев в коде.
- Округление половина вверх; сравнения с порогами по неокруглённым значениям, допуск 1e-9 относительно порога (разница строго меньше 1e-9*порог = равно).
- Границы порогов включительные.
- Некорректный ввод: ошибка с причиной у поля, никаких цифр.
- Коммитов нет.

## Запуск
`npm test` или `node --test "tests/*.test.js"` из корня проекта.

## Интерфейс модуля (`SubEconCalc`)
- `roundHalfUp(x, digits) -> number` (от нуля при равенстве, устойчиво к 1.005-подобным ошибкам)
- `formatRu(x, digits) -> string` (запятая как разделитель, ровно `digits` знаков: `5,0`)
- `parseNumber(text) -> {ok:true, value} | {ok:false, error}`; text: string|number|null|undefined; строка вида 1-3 цифры, разделитель, ровно 3 цифры («1,000», «0,500») отклоняется как неоднозначная; число типа number правилу не подлежит
- `validateInputs({price, margin, churn, cac, ratioThreshold, paybackThreshold}) -> {ok:true, values:{p,m,c,k,R,T}} | {ok:false, errors:{<поле>:string}}`; margin и churn в процентах, в values доли
- `formatNearThreshold(value, digits, reference, passes) -> string`: если `passes` ложно и `roundHalfUp(value, digits) === reference`, добавляет знаки (по одному, не больше 6), пока показанное не отличится от `reference`; иначе `formatRu(value, digits)`. Применение в блоке 2: LTV/CAC `(ltvCac, 2, R, ratioPass)`, окупаемость `(payback, 1, T, paybackPass)`, процент изменения `(changePctExact, 2, 0, false)`. Примеры: (2.997, 2, 3, false) -> «2,997»; (3, 2, 3, true) -> «3,00»; (12.0004, 1, 12, false) -> «12,0004»; (0.004, 2, 0, false) -> «0,004».
- `calculate(inputs) -> {ok:false, errors} | {ok:true, values, lifetime, ltv, ltvCac, payback, ratioPass, paybackPass, verdict:'scale'|'wait', lowChurnWarning:bool, noChangesNeeded:bool, changes}`
  - `changes` = null при `scale`, иначе `{price, margin, cac, churn}`, каждый `{status:'needed', target, changePct, changePctExact}` или `{status:'unreachable', reason:'over100'|'payback'|'zero', target}`; target уже округлён до 2 знаков в сторону выполнения порога (цена и маржа вверх, CAC и отток вниз; маржа и отток в процентах); `changePct` = округлённый до 2 знаков процент от показанной цели, `changePctExact` - он же без округления; `reason:'zero'` - цель CAC или оттока округлилась вниз до 0,00 (ввод 0 недопустим), target `null`
- `rankChanges(changes, difficulty) -> {order:[ключи needed по возрастанию оценки], unreachable:[ключи], first:ключ|null, scores:{ключ:число}}`; `difficulty` = `{price,margin,cac,churn}` со значениями `'easy'|'medium'|'hard'`, отсутствующий ключ = `'medium'`, иное значение бросает ошибку

Месяцы показываются с 1 знаком, в подстановке формулы с 2 (по макету): это забота блока 2, модуль отдаёт сырые значения.

## Задачи

### Задача 1: каркас, округление, формат
**Файлы:** создать `src/calc.js`, `tests/rounding.test.js`, `package.json` (только скрипт test)
**Отдаёт:** `roundHalfUp`, `formatRu`
**Критерий:** округление половина вверх (спека, «Округление»).
- Проверка `roundHalfUp(3.125,2)=3.13`, `(1.005,2)=1.01`, `(2.5,0)=3`, `(-35.185,2)=-35.19`, `(8.5714,1)=8.6`, `(0,2)=0`; `formatRu(5,1)='5,0'`, `formatRu(116.6667,2)='116,67'`, `formatRu(-35.19,2)='-35,19'`.
- Красный: функций нет (`TypeError ... is not a function`). Затем реализация, зелёный.

### Задача 2: разбор и проверка ввода
**Файлы:** изменить `src/calc.js`, создать `tests/input.test.js`
**Отдаёт:** `parseNumber`, `validateInputs`
**Критерий:** «Некорректный ввод даёт ошибку с причиной»; контрольный пример 5.
- Принимается: `"10"`, `"10,5"`, `"10.5"`, `" 1 000 "`->1000, `".5"`, `"5."`, число `7`, NBSP внутри.
- Ошибка (с непустой причиной): `""`, `"   "`, `null`, `undefined`, `"abc"`, `"5%"`, `"1e3"`, `"Infinity"`, `"1,2,3"`, `"1.2.3"`, `"1,000.5"`, `"+5"`, `"--5"`, `"1e400"`-подобная длинная строка цифр (бесконечность).
- Поле: `0`, `"0,0"`, `"-5"`, `"-0"` ошибка «больше нуля» для price, cac, ratioThreshold, paybackThreshold, margin, churn; margin и churn `100` приняты, `100,0001` и `101` ошибка.
- Все ошибки одного вызова возвращаются разом (несколько полей), без ключей цифр.
- Красный: функции нет. Реализация. Зелёный.

### Задача 3: основные цифры, вердикт, предупреждение
**Файлы:** изменить `src/calc.js`, создать `tests/figures.test.js`
**Берёт:** `validateInputs`. **Отдаёт:** `calculate` (без `changes`: пока `null`)
**Критерий:** примеры 1, 2, 6, 7, 8; границы включительные.
- Примеры (после округления): 1) lifetime 16,67; ltv 116,67; ltvCac 1,94; payback 8,57; `wait`. 2) ltv 266,67; ltvCac 6,67; payback 5,0; `scale`; `noChangesNeeded`. 6) 10,80,0.5,40: `lowChurnWarning` true, `ok` true, цифры есть. 7) 12,50,10,20: ltv 60,00; ltvCac 3,00 (сырое с допуском); payback 3,3; `scale`. 8) 10,50,2,60: payback 12,0; `scale`.
- Ветки: ratio 2,99 -> `wait` (ratioPass false, paybackPass true); payback чуть больше 12 -> `wait`; пользовательские пороги 2 и 6 дают другой вердикт на тех же числах; churn ровно 1% -> предупреждения нет, 0,99% -> есть; предупреждение вместе со `scale`; невалидный ввод -> `{ok:false}` без `ltv`/`verdict`; сверхмалый отток (1e-300) -> `ok:false` с ошибкой, не `Infinity`.
- Красный, реализация, зелёный.

### Задача 4: что изменить
**Файлы:** изменить `src/calc.js`, создать `tests/changes.test.js`
**Берёт:** `calculate`. **Отдаёт:** заполненный `changes`
**Критерий:** примеры 1, 3, 4; «недостижимо».
- Пример 1: price 15,43/+54,30; cac 38,88/-35,20; churn 3,88/-35,33 (target в процентах); margin unreachable over100, target 108.
- Пример 3: price 21,43/+114,30; cac 46,66/-53,34; margin unreachable over100 target 150; churn unreachable payback target null.
- Пример 4: price 13,34/+33,40; margin 66,67/+33,34; cac 60,00/-25,00; churn unreachable payback.
- Пример 2: `changes` null.
- Граница: 15,50,50,10 -> m*=1 ровно -> margin `needed`, target 100, +100 (не unreachable).
- Пользовательские пороги 2 и 6 на примере 1 дают другие цели (ручной расчёт: price max(2*60*.06/.7=10,29; 60/(6*.7)=14,29)=14,29/+42,90).
- Проверка согласованности (tests/roundtrip.test.js): показанные цели (`formatRu(target, 2)`), подставленные обратно в `calculate` на 6000 случайных и 3000 граничных вводов, дают `scale`. Цель оттока использует введённый R (R=2 -> 5,83; R=4 -> 2,91; R=5 -> 2,33). Цель, точно равная сотым (1, 69, 50, 5 -> отток 4,6), не теряет сотую.
- Красный, реализация, зелёный.

### Задача 5: порядок «с чего начать»
**Файлы:** изменить `src/calc.js`, создать `tests/rank.test.js`
**Берёт:** `changes`. **Отдаёт:** `rankChanges`
**Критерий:** примеры 1, 3, 4; веса; порядок при равенстве.
- Пример 1 (легко/средне/средне/трудно для price/cac/churn/margin): order [price, cac, churn], unreachable [margin], first price. scores: price 54,30; cac 70,40; churn 70,66.
- Пример 3 (все средне): order [cac, price]; unreachable [churn, margin]; first cac. Пример 4 (все средне): order [cac, margin, price]; unreachable [churn]; scores cac 50,00, margin 66,68, price 66,80.
- Смена трудности меняет порядок: пример 3 все средне -> [cac, price] (106,68 против 228,60); price «легко», cac «трудно» -> price 114,30, cac 160,02, order [price, cac].
- Пример 1 все средне: cac 70,40, churn 70,66, price 108,60: order [cac, churn, price]. Ничья: искусственные changes с равными оценками у всех четырёх -> order [price, cac, churn, margin]; оценки сравниваются после округления до 2 знаков (искусственные changes).
- Все unreachable -> order [], first null. `changes` null -> order [], first null.
- Неизвестная трудность -> ошибка.
- Красный, реализация, зелёный.

## Прикладные решения плана
- Оценка порядка = `roundHalfUp(|changePct|*вес, 2)`, где `changePct` уже округлён до 2 знаков (воспроизводимо вручную).
- Порядок среди недостижимых: цена, CAC, отток, маржа.

## На что смотреть ревьюеру
1. Дробные ошибки у порогов: ровно 3 и ровно 12 при вводе с дробными значениями, и 2,999 / 12,01 не должны проходить (задача 3).
2. Пользовательские пороги R и T реально используются в `changes`, не только 3 и 12 (задача 4).
3. Ввод: пробелы, NBSP, запятая, «1e3», «5%», очень длинные числа, бесконечность в результатах (задачи 2, 3).
4. Недостижимое: m*=1 достижимо, m* чуть больше 1 нет; отток недостижим только когда не проходит окупаемость (задача 4).
5. Загрузка без Node-окружения: `calc.js` не должен падать в браузере (`module`, `require` не определены) (задача 6).
